# 2026-05-09 ｜ TSS 基准锁定 + 5/10-5/17 plan 第三版

## 用户原始反馈

> "1，关于600tss的基准，我不认可。你可以查看我之前的每一周的tss，据我观测，我认为对于我而言，高强度负荷周的周tss在900-100tss，普通周在600-800tss，减量周才是400-600tss。2，对于我来说，150的tss也算不上大负荷的训练，我认为的大负荷在200-300tss。150tss的负荷我甚至可以背靠背训练。"

## 我的错误（撤回）

把 `build_memory.py` 输出的"近 4 周均 TSS=606.8"直接当成"用户常规周 TSS=600"基线，并据此设计 plan、解读 145 TSS 为"重负荷"。

**错因**：均值不等于"常规"。4 周均值 = 高/普通/低混合的算术平均。

## 历史数据验证（2026-04-06 至 2026-05-10 共 5 周）

## 新结构亮点

- **3 日背靠背训练**：Tue (149) + Wed (115) + Thu (127) = 391 TSS in 3 days
- 用户验证："150 TSS 我可以背靠背训练"，3 日中只有 Tue 触及 150
- 3 种刺激类型互补：race-rhythm (Tue) + 长 sustained (Wed) + W' 重建 (Thu)
- 周一 + 周五全休守住 user 偏好（"不喜欢天天练"）
- 5/13 SST 长拉填补用户 fast-twitch 体质缺的"长稳态"训练，**反而是练得最少的**

## 元教训：第 4 种 sycophancy 变种

之前已识别 3 种：
1. 顺着用户说
2. 用乐观估计给台阶下
3. 用"你在变好"叙事包装数据

**第 4 种**：把均值当作"常规"基线 — 让设计向均值倾斜，结果对高负荷选手保守、对低负荷选手过激。统计错误本身不是 sycophancy，但配合"我不想推太狠"的潜意识，就成了"以数据为名的保守"。

**新规则**：任何"基线"声称之前必须先看分布（max / median / P25-P75），不要用均值代替。
