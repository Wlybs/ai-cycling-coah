# 2026-05-09 ｜ 路骑优先 + 路况下功率匹配 HARD RULE

## 用户原始反馈

> "关于课表的执行，我倾向于路骑实现（除非很简单并且时间很短的课表，我才会偏向骑行台），因为这样最能模拟真实的爬坡节奏和变速。但是路骑会出现实际问题：间歇的时候是下坡，休息功率会很低，会和计划不符合。"

## 核心认知

W' 重建模型 (Skiba) 只看 `CP - P_recovery` 的差值时间积分，**不看精确瓦数**：

| P_recovery | τ (秒) |
|---|---|
| 150W | 28 |
| 100W | 25 |
| 50W | 22 |
| 0W (滑行) | 21 |

5min 恢复 = 10.7-14 个 τ → 99% 重建。**任何低于 CP 都行**，下坡滑行甚至比 150W 稍快。

**含义**：plan 里的 `5m Z1 组间` 表示"约 5 分钟的恢复"，不是"必须保持 150W 平均"。下坡 / 红绿灯 / 任何放松都符合。

## 训练效益的真正决定因素

| 维度 | 重要性 | 标准 |
|---|---|---|
| 工作段功率 | ⭐⭐⭐⭐ | ≥ 目标 90%（330W → 实际 315-345W 算达标） |
| 工作段时长 | ⭐⭐⭐⭐ | ≥ 目标 90%（90s → 80-100s 算达标） |
| 重复次数 | ⭐⭐⭐⭐⭐ | 必须达成（3 set × 3 cycles 不能砍） |
| 恢复段功率 | ⭐ | 不重要 |
| 恢复段时长 | ⭐⭐ | ≈ 目标即可（5min ≠ 必须精确） |

ICU 上传后看 **compliance 80%+** 即视为成功。

## 仅 3 类 session 必须上骑行台

1. **30/30 类 Tabata** — 节奏精确，路骑做不准
2. **赛前开腿** — 时间短，需要精准 anaerobic 通道激活
3. **HRV 警报后恢复 spin** — 控制不要骑过头

**其它一律路骑优先**：race-rhythm / OU / SST / Z2 长拉 等

## 本周 plan 路骑地形匹配

| 日 | Session | 地形方案 |
|---|---|---|
| 5/10 | 3×3×(90s 330W + 30s 450W) + 5min recover | **6-8min 中坡 × 3 趟**：每趟上坡 1 个完整 set，下坡滑行恢复。或长坡（林峰 16min）做 1.5 sets/趟 |
| 5/11 | 3×12min OU (2m 315W + 2m 270W)×3 | **15-20min 长坡 × 3 趟**：每趟做 1 set，下坡恢复 |
| 5/13 | 30/30 Tabata + Z2 base | **骑行台**（节奏精确）。Z2 部分可路骑 |
| 5/14 | Z2 + 4×8s 短爆 | 任何路况；8s 短爆找信号灯起步 / 缓坡起步 |
| 5/16 | 2×3min 315W + 30s 450W 开腿 | **4-5min 中坡 × 2 趟** + 末段 30s 冲。或骑行台（赛前精度优先） |

## 元规则（落 [[athlete]]）

**新 HARD RULE 2 条**：
1. 路骑优先（race-specificity），仅 3 类 session 上骑行台
2. 路骑功率匹配：工作段达标即可，恢复段功率随地形不需精确

未来所有 plan 设计必须附带地形建议（如这次的表格），不要默认用户在骑行台精确执行。

## 触发器

- 用户骑完上传后 ICU compliance < 80% → 检查地形是否匹配错了
- 用户反馈"找不到合适地形"→ 提供具体路线/segment 建议
- 用户偏好变化（如想多用骑行台）→ 更新 [[athlete]] 偏好
