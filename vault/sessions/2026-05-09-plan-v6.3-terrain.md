# 2026-05-09 ｜ Plan v6.3 — 真实地形 + commute TSS 整合

## 用户原始反馈

> "关于地形建议，我要和你补充我家附近可以执行训练的一些场地的信息：
> 1, mountain1，A面 2.23km 5.6%（5-6min）B面 2.52km 5.6%（6-7min），坡底距离我家 25km，骑行过去
> 2, mountain2，3.1km 6.6%（10-11min），坡底距离我家 30km，骑行过去
> 3, 其他坡距离都超过 30km 热身，过长，只能 4+2 过去。优点是减少热身时间提高效率；缺点开车 1h + 油费路费，所以 4+2 需要大负荷 TSS 训练才值得"

## 场地清单（落 [[athlete]] HARD RULE）

| 场地 | 距家 | 细节 | 适合 session |
|---|---|---|---|
| Mountain 1 A | 25km | 2.23km × 5.6% (5-6min) | 短间歇 / race-rhythm 单 set |
| Mountain 1 B | 25km | 2.52km × 5.6% (6-7min) | race-rhythm 完整 1 set / 短-中间歇 |
| Mountain 2 | 30km | 3.1km × 6.6% (10-11min) | OU 完整 1 set / SST 单组 / 中长间歇 |
| 远坡 (>30km) | 4+2 only | — | 仅 ≥200 TSS 大负荷日 |

平路充足 → Z2 / 长拉 / 神经短爆 / 恢复 spin 不需远征

## 4+2 经济性规则

**仅这种情况值得 4+2**：
- 单日训练 TSS ≥ 200
- 需要特定地形（如长爬、特殊坡度组合）
- 时间宝贵但要高强度

**race week / 减量周 / 平日训练** → 优先 Mountain 1/2 + bike out

## TSS 估算契约（HARD RULE）

| 项目 | TSS add-on |
|---|---|
| 25km bike out @ Z2 (60min) | ~40-45 TSS |
| 30km bike out @ Z2 (75min) | ~50-55 TSS |
| 来回（双向 Z2） | 80-110 / 100-130 TSS |

**plan 标 target_tss 必须含 commute**，不能只标 workout 段。

## 路骑 vs Trainer 决策树

```
Session 类型 → 决策
├── 30/30 类 / Tabata → Trainer (节奏精度 HARD)
├── 赛前开腿 → Trainer (精度 HARD)
├── HRV 警报恢复 → Trainer (控制 HARD)
├── Race-rhythm (短爆 + 稳态) → 路骑 Mountain 1 B/A (匹配地形)
├── OU (12min sustained) → 路骑 Mountain 2 OR Trainer (代谢刺激不依赖地形)
├── SST 长拉 (15min) → 路骑 Mountain 2 OR Trainer
├── Z2 / 长拉 / 神经短爆 → 门口平路
└── 远征 (4+2) → 仅 ≥200 TSS 大负荷日
```

## 元教训：plan 设计前必须知道场地

之前 v6/v6.1/v6.2 没问场地，全按"理想骑行台执行"算 TSS。结果 5/10 标 92 TSS 但用户实际走路骑会到 175 TSS。**plan 与实际严重脱节**。

**新规则**：plan 设计前必须确认：
- 用户是否计划路骑 / trainer / 4+2
- 路骑距离 + 地形匹配
- 估算 commute TSS 加入 target_tss

## 触发器

- 后续 plan 必须问"地形 / 执行方式"
- 用户实际 ride 上传后比对 TSS（plan 估 vs 实测）→ 校准 commute add-on 系数
- 场地信息扩展（新 Mountain 3 等）→ 更新 [[athlete]] 场地清单
